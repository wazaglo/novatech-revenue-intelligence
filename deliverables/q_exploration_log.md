## Reflection

- **Where Q agreed with the dashboard:** channels (Q1), resolution times (Q3), top-10 at-risk accounts (Q4), campaign profitability (Q5). Q's per-channel response math matched the source CSV to the decimal, and it correctly surfaced the cross-dataset account risk list that requires the joined model.
- **Where Q disagreed or struggled:** average deal size by company size (Q2). Q computed over the unified join where fan-out duplicates each deal (63,420 rows vs 499 deals), which deflated per-tier averages. The published dashboards avoid this by sourcing Sales from the 499-row CRM dataset. The Topic's custom instructions (documented planted duplicates and fan-out warnings) reduced but did not eliminate this - semantic layers can't fix a row-grain mismatch; model design does.
- **When to use Q vs the dashboard:** Q for exploratory, ad-hoc, cross-dataset "what if / top N" questions and narrative summaries; the dashboard for governed, repeatable KPI reads (win rate 63.1%, revenue $707,201) where a single certified definition must not vary between asks. Rule of thumb adopted: *if the number will be quoted, read it off the dashboard; if the question is new, ask Q, then verify against the dashboard before quoting.*
